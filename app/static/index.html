Textile rolls and fabric remnants

Not built. This tab is here so the platform's scope is honest.

Fabric needs its own engine: pattern pieces are irregular shapes, the roll has a fixed width, grain and stretch restrict orientation, and colour or dye batch must match. Rectangle nesting would give misleading yields.

What it would take: irregular-shape nesting (no-fit polygons or a library such as SVGnest), pattern files from buyers (DXF or marker files), and field data from a cluster such as Tiruppur. It would plug into the same core: pooling, recovery plan, deals and ledger work unchanged.

How the platform is built

One shared core, one engine per kind of resource. A new resource type is one new engine file; nothing in the core changes.
